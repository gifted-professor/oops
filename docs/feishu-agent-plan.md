# 飞书动作与"Oops 替你去做"

## 已实现（2026-10-10 上线）

- **机器人身份**：服务器应用 `cli_aa4f5425caf85cc8` 已开通机器人和 37 项机器人权限，并订阅了卡片回调 `card.action.trigger`（长连接）。对外动作都用 `lark-cli --as bot`。代码在 `scripts/feishu_actions.py`，由环境变量 `OOPS_FEISHU_BOT=1` 开启。
- **会后纪要**：会议结束 90 秒后，先等 DeepSeek 起好会议名称，再按"宁缺毋滥"整理出概述、决定、会后待办、讨论要点、待查问题和约好的跟进。每条都必须对得上原话编号，负责人只能是团队成员。
  - 怎么算结束：手机报的结束时间；App 被杀后下次打开补报的（估算）；录音上传带的；都没有时，最后一句之后 20 分钟没有新句子（至少 5 句）。
  - 之后：
  - 建飞书纪要文档，共享给参会人。
  - 私聊参会人每人一张卡片：至少说过 3 句的团队成员，外加记录这场会的人。
  - 写入多维表格"Oops 会议台账"（会议、决定、待办三张表）。
  - 没有实质内容的会议什么都不发。
  - 只处理功能上线之后结束的会议。
- **卡片按钮**：
  - 建日程：机器人日历发邀请，只邀请点按钮的人和会上点名的人。
  - 帮我查、做成 PPT、整理报告：交给 Mac 助手。
  - 打开纪要。
  - 新任务卡片上的"不是我的"：提醒记录这场会的人改负责人。
- **新任务通知**：飞书任务建成并回读后，私聊负责人，附原话。
- **会上自动查问题**：有人提了问题、3 分钟没人答，模型判断值得查，就自动交给 Mac 助手。每场最多 3 次。
- **Mac 助手**：
  - `scripts/oops_mac_agent.py` 由 launchd 常驻（`deploy/mac/install-mac-agent.sh`），凭据 `OOPS_AGENT_TOKEN` 独立于 App 的凭据。
  - 每 10 秒向 `/v1/agent/poll` 领一次任务，在 `~/Oops/jobs/` 里用 `claude -p --restricted` 完成：只能联网搜索、读写本任务目录，不能运行命令；`~/.ssh`、`~/.oops-agent`、`~/.claude` 等另有拒绝规则。
  - PPT：Claude 只写大纲 `outline.json`，由 `scripts/oops_slides.py` 渲染成 pptx。
  - 任务目录保留 30 天。
  - 文件分块上传，结果由机器人建文档或私聊发文件。
  - 暂停：`touch ~/.oops-agent/paused`。

## 原始方案（2026-10-09）

目标：Oops 不只记下会议里说了什么，还替人把事做掉。先在飞书里做（日程、消息、表格、文档），再在用户点了允许之后，到用户电脑上做（PPT、资料报告、查会上卡住的问题）。现在 Oops 主要靠"听"；以后逐步加上"看""知道上下文""开口说"和"动手做"。

## 现状

- 服务器只接了一条飞书链路：后端调用 `lark-cli task +create --as user`，以**林春源的个人身份**建飞书任务。
  - 流程是：草稿 → 手机上确认 → 创建 → 回读校验，用 `op_id` 防止重复创建（`scripts/local_backend.py:1819-1876`）。
- 服务器上的飞书应用是 `cli_aa4f5425caf85cc8`（Oops 组织）。它只开了任务读写和通讯录查人两类权限。日程、消息、表格、文档都还没接。
- 本机 Mac 上的 lark-cli 用的是另一个应用 `cli_a92167f370b89cb2`，权限很全：
  - 日历：建日程、查忙闲、推荐时间。
  - 消息：以用户或机器人身份发送，支持卡片。
  - 多维表格、电子表格、幻灯片、文档。
  - 事件长连接（`event consume`）：可以收卡片按钮回调，不需要公网回调地址。
  
  所以这些能力是现成的，缺的是给服务器那个应用开权限，以及业务逻辑。

## 原则（所有动作都一样）

1. **先草稿后执行**：会议里识别出的意图只生成草稿。写飞书、发消息、动用户电脑之前，必须有人确认，在手机上点一下或在飞书卡片上点一下都算。
   - 沿用现有的 `op_id` 幂等、先记日志再执行、回读校验这套流程。每类动作只是换一个执行器。
2. **用机器人身份对外**：发消息、发日程邀请、写团队台账，都用 Oops 机器人（应用身份）。
   - 不再全部挂在林春源一个人的令牌上。这样不怕个人令牌过期，别人收到的也是"Oops"发来的，而不是"林春源"。
   - 只有必须"以本人名义"的事才用个人授权，比如在自己的日历上建日程、以自己名义发消息。这类授权由每个人自己点允许。
3. **信任分级**：
   - 只读和查资料：自动做，结果安静地推到手机上。
   - 写到团队可见的地方（消息、日程、表格、文档）：确认一次再做。
   - 动用户电脑：只在用户自己点了允许的设备上做，限定工作目录，每次都能看到 Oops 做了什么。
   - 付款、删除、改账号：不做。
   - 以后可以让用户把某一类动作设成"以后直接做"。
4. **做完要回报**：每个动作都给出链接和结果，失败时说清楚原因。不能说"已完成"却没回读到结果。

## 一、飞书里能做的事

| 能力 | 会议里的触发 | 做法（lark-cli / OpenAPI） | 身份 |
|---|---|---|---|
| 建日程 | "周五下午三点再对一下" | 先用 `calendar +freebusy` / `+suggestion` 查参会人有没有空，生成日程草稿（时间、参会人、关联会议纪要），确认后用 `calendar +create --attendee-ids` 建，并回读 | 机器人日历"Oops 会议"发邀请；或用组织者本人授权 |
| 机器人发消息 | 会议结束、任务分派、到期前、冲突提醒 | `im +messages-send` 发**卡片**；按钮回调走 `event consume card.action.trigger`（长连接） | 机器人 |
| 团队台账（多维表格） | 决定或待办被确认时 | 每个团队或项目一个多维表格，分会议、决定、待办、问题四张表；确认后用 `base +record-batch-create` 追加，待办记录关联飞书任务 guid | 机器人 |
| 临时表格 | "把刚才的报价列个表" | `sheets` 新建电子表格，把对话里的数字和条目整理进去，发链接 | 机器人，并共享给参会人 |
| 会议纪要文档 | 会议结束 | `docs +create` 生成纪要：决定、待办、待核对、原话出处，链接放进卡片和日程描述里 | 机器人 |
| 任务（已有） | 待办确认 | 现有 `task +create`；之后改成机器人创建并指派 | 改为机器人 |

### 机器人卡片（第一批最值得做）

1. **会后纪要卡**：会议结束 1–2 分钟后发到团队群（或每位参会人私聊）。
   - 内容：标题、时长、决定 N 条、待办（负责人、期限）、待核对数。
   - 按钮：查看纪要、去核对、全部确认。
2. **任务分派卡**：私聊发给被指派的人，带原话出处。
   - 按钮：接受、不是我、改期限。
   - 用户点按钮后，事件回到服务器，更新飞书任务和台账，再更新这张卡片。
3. **到期提醒卡**：期限前一天私聊提醒负责人。
4. **冲突提醒卡**：现在的项目冲突提醒除了在手机上显示，也可以发到项目群。

## 二、会上的问题没人解决时，自动去查

现有的标签有决定、待办、约束，再加一类**问题**（谁问了什么）。

1. **识别**：一句话被标成问题后，Oops 记下这个问题，并留意接下来几分钟的对话里有没有回答（用模型判断一小段窗口）。
2. **触发**：问题提出 3 分钟后还没人回答，或者散会时仍然没有答案，就作为候选。也可以有人直接说"Oops 查一下"。
3. **去查**：
   - 先查自己的资料：往期会议原话、项目记忆、飞书文档（`docs +search`）、飞书消息（`im +messages-search`）。
   - 内部找不到再上网查。
   - 每个答案都附来源。
4. **送达**：不打断说话。手机上安静地出现一张"Oops 查到了"卡片，用户可以点"放进纪要"或"发到群里"。
5. **约束**：
   - 每场会最多查几次，设费用上限，同一个问题不重复查。
   - 涉及个人隐私的问题不查。
   - 内部来源优先，外部来源要标明。

## 三、在用户电脑上做事（桌面助手）

先说清楚边界：**大部分"做事"其实不需要用户的电脑。**查资料、写报告、做飞书幻灯片（`slides +create`）、写飞书文档，服务器上的代理就能做完，结果直接是飞书链接。桌面助手只用来做**必须在本机做**的事：

- 用本机的 PowerPoint、Keynote、Excel 产出文件。
- 读写用户本机的文件。
- 用用户浏览器里已经登录的网站。

### 设计

- **形态**：Mac / Windows 上一个常驻的小程序，用一次性配对码和用户的 Oops 账号绑定。安装和授权都要用户自己点。
- **任务从哪来**：服务器有一个任务队列。手机确认后，任务进队列；桌面助手用长连接领取任务，执行，再回报进度和产出。
- **执行**：用 Claude Agent SDK（或 Claude Code）在限定的工作目录（如 `~/Oops/`）里运行，配好工具：
  - 生成 PPT 文件。
  - 网页搜索。
  - 本机 lark-cli（用户本人授权）。
  - 可选的屏幕操作，默认关闭。
- **权限**：
  - 工作目录之外的读写、打开应用、操作屏幕，每次都在桌面上弹出确认。
  - 用户可以随时暂停。
  - 所有操作都有日志，可以回看。
- **第一批任务**：
  - 根据会议内容做 PPT 初稿：飞书幻灯片优先，本机 pptx 作为备选。
  - 会上提到的资料搜集，写成一页报告。
  - 继续查会上没解决的问题（第二节里，需要本机资料的那部分）。

## 四、走向"贾维斯"：从听到五感

| 感官 | 现在 | 下一步 |
|---|---|---|
| 听 | 收音、转写、说话人识别、语音唤醒 | 更准的说话人识别；会中自动识别问题和意图 |
| 看 | 无 | 拍白板或屏幕后识别文字，并入纪要；桌面助手可看当前屏幕（需授权） |
| 知（上下文） | 往期会议、项目记忆 | 飞书日历（这是什么会、谁参加）、相关飞书文档、任务进度 |
| 说 | 无 | 通过耳机小声播报："刚才的问题我查到了""这和上周的决定不一致" |
| 做 | 建飞书任务 | 日程、消息卡片、台账、文档、PPT、桌面任务 |

关键不在加多少种感官，而在于 Oops **主动提议、经确认执行、事后回报**这个循环足够可靠，让大家愿意把事交给它。

## 建议的推进顺序

1. **会后纪要卡和团队台账**：只用到机器人身份和现有数据，最快能让全组每天看到效果。
2. **日程草稿**：识别时间表达，查忙闲，确认后发邀请。
3. **卡片按钮回调**：接受任务、改负责人。要在服务器上跑 `event consume` 常驻进程。
4. **问题自动去查**：先做"散会时没解决的问题"，再做会中 3 分钟触发。
5. **桌面助手**：先做"根据会议做 PPT 初稿或资料报告"，产出是飞书链接或本机文件。
