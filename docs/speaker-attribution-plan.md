# 每句话对应到人：句内拆分 + 校准置信度 + 任务分级（执行版）

## 背景

目标：不管是轮流说还是同时说，转写里每一段都能标到人，并带上可信的置信度；任务负责人按置信度分级。"超精准"的意思是：**模型判为高可信的部分错误率有统计保证；没把握的显示为建议或待定，不猜。**

调研确认的现状：
- 豆包大约每 20 秒切一句，一句里常有好几个人说话（162 句中有 149 句 ≥19 秒），所以必须**句内按字拆分**。ASR 有逐字时间，中位约 120 ms。
- 句内拆分已经写好（`scripts/local_backend.py` 的 `Speakers.split`），但没启用，原因有两个：
  - 人工真值是 0 句；
  - 只要服务器上存在 `voiceprints.json`，拆分就不会开启。
- 正式拆分不检测重叠；只有试验预览 `scripts/speaker_preview.py` 有重叠保护。
- 在实际手机链路上，真实句子的分数在 0.40–0.51，大多被判为未知。

已定的决定：
- A 档负责人一键确认后，才创建飞书任务。
- 真值来自 DJI 55 句，加上实际链路的实录。
- 同时说话的部分只检测，给出两个候选。

两轮评审共 10 点，全部采纳。第二轮新增四条规则：
- 零错时不能只看 bootstrap 结果，要用精确二项上界；样本不足时返回 `insufficient_evidence`。
- 本人类低于 A 档时，只给"建议负责人"，不预填。
- 晚到的模型结果不能覆盖人工编辑。模型给出的叫"高可信"，人工核实后才叫"已确认"。
- `confidence` 定义为"段内主导说话人归属正确"的概率；`owner_confidence` 单独对应承诺短语归属事件。保留集看过之后就成为回归集，不能再用来验收。

**工程顺序不变。严格 A 档开关默认关闭**，等真实标注达到足够证据后才开启。

## 阶段 0：真值

1. 四人在实际链路（Hollyland → Mac → 手机 remote）下重录声纹。
2. 给 `scripts/mac_audio_bridge.py` 加 `--record`，录制文件只存本机 `evidence/`，不传香港或其他新增服务；现有火山 ASR 音频链路仍照常运行。每次手机连接单独录制成功发送的 PCM，并保存本机时间、帧数与断连元数据；不把断连前后拼成一场连续会议。
   - **至少录两场**会议：一场作开发集，一场作保留集，按场次划分。
   - 会上要自然出现足够多的"我来做"式承诺。
3. 用 `scripts/asr_words_probe.py` 生成逐字时间，再用 `voiceprint_split.py prepare` 出题。
   - 实际链路集单独建一份 manifest。
   - DJI 集维持原划分：0236 作开发集，0238 作保留集。
4. 用现有盲标注页 `voiceprint_split.py serve` 标注：DJI 55 句 + 实录约 40 句以上。
   - 标注页只改一处：可以切换题集。
5. **预期的证据量**（精确二项，单侧 95%）：
   - A 档错名上界要 ≤2%：零错时需 ≥149 个独立 A 档段，错 1 次需 ≥236 个。
   - 本人负责人准确率要 ≥95%：零错时需 ≥59 条，错 1 次需 ≥93 条。
   - 第一轮大概率达不到，结果会是 `insufficient_evidence`。这种情况下 A 档保持关闭，在模型和目标样本量冻结后，盲累积后续独立会议标注；到预先约定的截止条件后只做一次最终判定，不逐场检查直到通过。

## 阶段 1：后端拆分 v2（固定声纹，不做自适应）

新模块 `scripts/speaker_attribution.py`，由 `Speakers.split` 调用。复用现有的 `align_words`、`voiceprint_decision`、`adjudicate_segments`、`viterbi_speakers`。

1. **换人点**：融合两路信号。
   - 声纹滑窗 Viterbi。
   - pyannote 的换人帧和重叠帧，复用 `SpeakerPreview.activities`。
   - 切点只落在字间隙上。
2. **整段打分**：单人段用整段音频重新打分；上一句最后一个非重叠、非近似且高可信的说话人，作为下一句开头的弱先验；仅同一会话且时间连续时有效，乱序、间隔过长、断连、声纹改动与会话结束清除，不能跨会话复用。
3. **重叠**：
   - 重叠覆盖的字标 `overlap: true`、`speaker: null`。
   - 附两个 `candidates`，固定为 C 档。
   - 不默认归给主讲人，也不参与负责人判定。
4. **Jev（只看文字）**：
   - 候选切点上是否换人，作为特征。
   - 点名只作弱反证，限明确的直接称呼；引用、自称、转述、歧义不作硬排除，不能覆盖锁定声纹。
   - 复核时只能在声纹前二名里选，要求概率 ≥0.7，且不改已锁定的段。
5. **校准置信度，定义写死**：
   - `confidence` = P(该段的预测说话人 = 该段内非重叠、可辨认字中 ≥90% 的人工标注说话人)。
   - 这是**段内主导说话人归属正确**的概率，不是全段每一个字正确，也不是随机一个字正确。本人任务单独定位承诺短语：成功事件为该短语内所有可辨认实词均属于预测负责人；独立拟合和验收 `owner_confidence`，禁止直接复制段概率。
   - 用开发集拟合逻辑回归（numpy 实现）。
   - 按字准确率作为另一个指标单独报告，不混用。
6. 每段输出 `speaker, confidence, tier, overlap, candidates[{name,score}], source, approx`。

## 阶段 2：评估、冻结、开关

修改 `scripts/voiceprint_split.py` 的 `evaluate`、`gates`、`metrics`。

1. **只在开发集上做选择**。以下几项都在开发集上定好后冻结：
   - 是否用 Jev（去掉现有代码在保留集上计算 `keep_jev`）；
   - 校准器；
   - A/B 阈值；
   - 拆分参数。

   保留集只跑一次判定。
2. **统计规则**：
   - 判定单位是 **A 档段**，成功或失败按上面的段级定义计算。
   - 用 Clopper–Pearson 精确二项算单侧 95% 上界。
   - 零错或少错时也只看这个上界，不用 bootstrap 区间做判定。
   - 同一句里的段彼此相关，所以另外按句聚类报告：上界同时按"句"为单位算一次：仅计含 A 段的句子，任意一个 A 段失败则该句失败，两者都要达标。无 A 段时返回证据不足。句级独立性也必须说明；同一会议的句不能自动视为跨会议独立证据。
   - 样本量不足以达到目标上界时，返回 `insufficient_evidence`。这不算通过，也不算失败，A 档保持关闭。
   - bootstrap 只作为描述性报告。
3. **两个开关**：
   - **拆分显示开关**：现有最低线全部通过即可开启。最低线是：按字准确率比整句基线高 10 个百分点、错名 ≤5%、换人召回 ≥70%、短插话召回 ≥50% 且错 ≤10%。开启后，所有名字只显示为"建议 / 待核对"，不预填负责人。
   - **严格 A 档开关**：A 档段错名上界 ≤2%，且按句上界也达标。开启后才显示"高可信"并预填负责人。
   - 两个开关都以实际链路集为准；DJI 集单独报告。
4. **保留集治理**：
   - 看过保留集后，如果修改了方案、参数或特征，旧保留集降为**回归集**，新版本必须用新的独立场次来验收。
   - 验收文件记录保留集场次 ID 和"已使用"状态，同一个保留集不能给两个版本签发验收。
   - 单场保留集的结果标注为"单场结果，不代表跨会议稳定性"。跨会议的稳定性靠后续多场累积来证明。
5. **指纹**：覆盖判定代码、`speaker_attribution.py`、CAM++ 模型、pyannote 模型、校准器，以及**线上实际使用的声纹向量哈希**。
   - 用它替换"存在 `voiceprints.json` 就不开启"的规则。
   - 有人重录声纹后，拆分自动关闭。在 Mac 上一条命令重跑验收（只拉取向量，不传音频），通过后再部署。

## 阶段 3：任务分级

1. **重写 `commitment_evidence` / `self_owner`**（`local_backend.py`）：
   - 定位具体的承诺短语，按字区间判断。
   - 排除"我们 / 咱们 / 大家 / 一起"这类集体承诺。现在"我们下周完成"会被误判为本人承诺。
   - 短语跨段或落在重叠里，不判定。
   - 一句里有多个承诺时，不合并。
2. **负责人分为两个字段**：
   - `owner`：已判定的负责人，会预填。
   - `suggested_owner`：模型建议，不预填，在界面上作为可点选的建议。
3. **分档规则**：

   | 类别 | A（严格开关开启时） | B | C |
   |---|---|---|---|
   | 本人（"我来做"） | `owner` = 短语所在段的说话人，标"高可信" | `owner` 留空；`suggested_owner` = 该段说话人，标"建议 · 待核对" | `owner` 留空，候选按分数排序 |
   | 点名（"春源，你……"） | 文字规则明确时，`owner` = 被点名的人（不依赖声纹），说话人只用来排除"自己点自己" | 规则有歧义时，只给 `suggested_owner` | 无法判断 |

   - 严格开关关闭时，两类均不得预填负责人，最高只能到 B。严格开关只是共同前提，另设独立的本人归属与点名关系验收门禁；未通过相应门禁时只返回建议。点名语义校准和验收不能用声纹结果替代。
   - 本人类进入 A 档，需要保留集上的本人负责人准确率下界达标（≥95%，按阶段 0 第 5 条的样本量），以此替换现有"≤20 条零错"的闸门。
4. `/v1/actions/draft` 返回以下字段：`owner`、`suggested_owner`、`owner_source`（named/self/none）、`owner_confidence`、`tier`、`reason`、`owner_candidates`。

## 阶段 4：手机端与整条数据链

- **解析**：
  - `backend/OopsApi.kt` 的 `usableSegments` 改为逐段接受：坏段保留原文并降为未知，拼起来必须等于原句，不能漏字。整组文字或全局边界不可信时整句降为未知；局部坏段保留原文但 `speaker=null, confidence=null, tier=C`。
  - 解析 `runner_up` 和段的新字段，涉及 `backend/ApiJson.kt`，以及 `buffer/TranscriptBuffer.kt` 里的 `SpeakerSegment`。
- **晚到结果不覆盖人工**（`engine/OopsEngine.kt`）：
  - 草稿状态要记录哪些字段被用户改过：负责人、事项、时间。
  - 模型结果晚到时，只更新 `suggested_owner`、档位、候选和理由，不改用户已选或已编辑的字段。
  - 已提交的确认快照（`store/ActionOperationStore.kt`）不可变。
  - 纪要列表的负责人提示也遵循这个规则。
  - 修掉 `?: u.speaker`，它会把 ASR 的编号当成名字。
- **措辞**：
  - 模型 A 档显示"高可信"；B 档显示"建议 · 待核对"；重叠显示"多人同时说"。
  - 只有人工选择或核实过的才显示"已确认"。
  - 停止会议时提醒"N 条负责人待确认"。
  - 涉及 `bridge/BridgeJson.kt`、`assets/web/app.js`。
- **同步链**：
  - `buffer/SessionIndex.kt` 的 `setSpeaker` 要带上新字段。
  - `Candidate`、`ApiJson.candidate` 和草稿请求要带上段的置信度和重叠信息。
  - `backend/MeetingSync.kt` 和香港 `scripts/meeting_features.py` 的 `candidates()` 校验要加入分段：字段白名单、数量和长度上限、拼接后必须等于原文。
- **部署**：沿用 `deploy/voiceprint-sources-upgrade.py` 的备份和回退模式。新模块、校准器和验收文件一起打包。两个开关上线时默认关闭。

## 验证

- **单测**：
  - 切点融合；重叠固定为 C 档。
  - 校准和分档；`confidence` 按段级定义计算。
  - Clopper–Pearson 在零错、少错、样本不足时的边界：例如 20 条零错的上界是 0.139，此时返回 `insufficient_evidence`。
  - 冻结后，保留集不能影响任何参数；已使用的保留集不能再签发验收。
  - 指纹变化时，拆分自动关闭。
  - 本人判定的反例：我们、跨段、重叠、多承诺。
  - B 档只给 `suggested_owner`。
  - Android 逐段接受时不漏字；晚到结果不覆盖人工编辑和确认快照。
  - 香港同步的分段校验。
- **离线**：两套题各走一遍"开发集冻结 → 保留集一次判定"，报告：
  - 各档精确率；
  - A 档覆盖率；
  - 精确上界和按句上界；
  - 开关状态（通过 / 未通过 / `insufficient_evidence`）；
  - 重叠表现；
  - 延迟。
- **线上**：
  - 先在香港部署，两个开关都关；拆分显示开关只有在最低线通过后才开。
  - 在实际链路上真机跑一场会议，抽查结果。
  - 用户改负责人的记录作为后续真值来源，但不能直接用于验收。


## 执行契约补充（2026-10-08）

- 未拟合或未验收时 `confidence` / `owner_confidence` 为 null，余弦 score 和 Jev 概率不能冒充校准概率。候选最多两名，候选分数只是相似度；没有充分候选时允许少于两名，不补造名字。
- `approx=true`、unknown、overlap、承诺跨段、集体承诺和对齐失败均禁止进入本人 A；重叠固定 C，不返回建议负责人。多个承诺逐个保留字符区间及证据，当前单草稿不能确定一个行动时返回待拆分，不合并负责人。
- 段的 A 显示、本人预填、点名预填分别受共同严格开关与各自验收证据控制；校准特征、阈值、语义规则、模型、声纹快照和验收截止规则必须属于同一版本。首版两开关与两类负责人门禁全部默认关闭，禁止旧 schema 验收免审核开启。
- 验收的最终场次清单和最低有效样本目标在开发阶段冻结。尚未达到样本目标时不查看保留预测/真值指标，不消费该集合；最终判定后登记已消费。相同冻结版本允许复现同一结果但不得重新签发；根据结果改版后只能使用新独立保留集。首版采用固定查看时点，不实现逐场提前通过。
- 点名负责人成功事件是该行动实际被明确指派给此人；本人成功事件是承诺短语归属及行动绑定均正确。准确率使用单侧 95% 下界 ≥95%（等价错误率上界 ≤5%）。不能凭命名规则看起来明确就进入 A。
- `owner_source` 描述模型提取依据，另用人工编辑/确认状态标识人工选择；人工确认不把 confidence 改为 1，不改变模型 tier。回刷保护负责人、事项、日期、约束和已提交 op_id/请求快照。
- 真值的承诺标注须支持每个承诺的字符区间、类型、负责人及行动绑定；保留旧 self_owner 单承诺数据的只读兼容，多个承诺不能复用一个承诺人标签。
- 真值盲标不显示模型候选；用户修改负责人的日志只作为待核实反馈，不能自动当验收真值。独立会议划分、来源/设备、样本抽样方法与限制必须写进报告。
- Jev 的可变别名不能作为冻结版本。开发集可记录请求模型、URL 与实际返回 engine 并离线比较；当前提供方不能证明不可变版本时，最终冻结 `use_jev=false`，重新按该声学版本拟合校准器，不能把有 Jev 的校准器用于无 Jev 线上。后续只有能固定提供方版本并进入验收指纹，才允许启用。
- 部署包只包含源码、所需模型/校准器与验收元数据，不携带 PCM、密钥、人员映射或覆盖线上声纹。部署前现场状态检查、备份、认证及只读/隔离草稿测试，失败回滚；未经真实验收不宣称识别准确率或真人接受通过。
